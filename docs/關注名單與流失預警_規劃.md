# 關注名單與流失預警 — 規劃書

> 以**會期一年**為基準設計，適用於華地產線上鑽石分會簽到系統

---

## 一、會期假設與時間軸

| 項目 | 設定 |
|------|------|
| 會期長度 | 1 年 |
| 例會頻率 | 每週四 1 次（可依實際調整） |
| 一年例會數 | 約 48～52 場 |
| 會期起迄 | 依資料庫實際會議日期自動推算（例如：最早會議日～最晚會議日，或依 admin 設定） |

---

## 二、指標定義

### 2.1 既有指標（沿用）

| 指標 | 說明 |
|------|------|
| 總會議數 | 區間內有舉辦的例會場次 |
| 出席次數 | 該會員實際出席次數（含遲到、早退、代理） |
| 缺席次數 | 總會議數 − 出席次數 |
| 出席率 | 出席次數 ÷ 總會議數 × 100% |

### 2.2 新增指標（本功能專用）

| 指標 | 計算方式 |
|------|----------|
| **連續缺席次數** | 從「最近一次例會」往前數，連續幾場沒有簽到記錄 |
| **最後出席日** | 該會員最近一次有簽到記錄的會議日期 |
| **距今天數** | 今天 − 最後出席日（天數） |
| **出席率趨勢** | 前半年出席率 vs 後半年出席率（會期過半後啟用） |

---

## 三、風險等級與門檻

以**會期一年、約 48 場例會**為基準：

| 等級 | 名稱 | 觸發條件（符合任一即列入） | 關懷優先序 |
|------|------|---------------------------|------------|
| **🔴 高風險** | 瀕臨流失 | ① 連續缺席 ≥ 4 次<br>② 出席率 &lt; 15% 且總會議數 ≥ 10<br>③ 最後出席距今 &gt; 60 天 | 1（最優先） |
| **🟠 中風險** | 需要關注 | ① 連續缺席 2～3 次<br>② 出席率 15%～35%<br>③ 最後出席距今 30～60 天 | 2 |
| **🟡 低風險** | 觀察名單 | ① 連續缺席 1 次<br>② 出席率 35%～50%<br>③ 趨勢下降（後半期比前半期低 20% 以上） | 3 |

**說明**：
- 連續缺席 4 次 ≈ 約 1 個月未出席
- 60 天未出席：高風險
- 30～60 天：中風險

## 四、時間區間設定

| 用途 | 區間 | 說明 |
|------|------|------|
| 主要統計區間 | 依使用者選擇 | 本週、本月、本季、本會期（預設） |
| 連續缺席 | 最近 N 場例會 | 以「最近有舉辦的例會」為起點往前數 |
| 趨勢比較 | 會期前後半 | 會期過半後：前半期 vs 後半期出席率 |
| 會期定義 | 自動推算 | 取資料庫會議日期最小～最大，或由 admin 設定會期起迄 |

## 五、功能架構

### 5.1 統計報表 — 新增「關注名單」Tab

```
統計報表
├── 原「統計」Tab（出席率一覽）
└── 關注名單 Tab（新）
    ├── 摘要區：高風險 N 人、中風險 N 人、低風險 N 人
    ├── 篩選：風險等級、專業別
    ├── 表格：編號、姓名、專業、出席率、連續缺席、最後出席日、趨勢、風險等級
    └── 匯出 CSV
```

### 5.2 表格欄位

| 欄位 | 說明 |
|------|------|
| 編號 | 會員 ID |
| 姓名 | 會員姓名 |
| 專業別 | 會員專業 |
| 出席率 | 該區間出席率 % |
| 連續缺席 | 最近連續未出席場次 |
| 最後出席日 | 最近一次有簽到的會議日期 |
| 距今天數 | 今天與最後出席日的天數差 |
| 趨勢 | 上升 / 持平 / 下降（會期過半後顯示） |
| 風險等級 | 高 / 中 / 低 |

### 5.3 排序與篩選

- **預設排序**：風險等級（高→中→低）→ 連續缺席（多→少）→ 出席率（低→高）
- **篩選**：風險等級、專業別

## 六、API 設計

### 6.1 擴充 `/api/statistics/member-attendance`

**需求**：在既有出席統計基礎上，額外回傳：

- `consecutiveAbsences`：連續缺席次數
- `lastAttendanceDate`：最後出席日
- `daysSinceLastAttendance`：距今天數
- `trend`：`'up' | 'flat' | 'down'`（會期過半後）
- `riskLevel`：`'high' | 'medium' | 'low' | null`

**Query 參數**：沿用 `start`、`end`；可選 `includeRisk=true` 啟用風險計算。

### 6.2 或新增 `/api/statistics/care-list`

- 專門負責「關注名單」邏輯
- 輸入：`start`、`end`（會期區間）
- 輸出：依風險排序的會員列表 + 上述指標

## 七、實作順序建議

| 階段 | 內容 |
|------|------|
| 1 | 擴充 member-attendance API：計算連續缺席、最後出席日、距今天數 |
| 2 | 加上趨勢比較（會期前後半）與風險等級 |
| 3 | 統計報表新增「關注名單」Tab、表格與篩選 |
| 4 | 匯出 CSV |
| 5 | （選配）關懷紀錄、提醒通知 |

---

## 八、注意事項

1. **會議日期順序**：連續缺席需依「例會日期」正確排序，不可用簽到時間亂序計算。
2. **新會員**：剛加入、會議數很少的會員，出席率易偏極端，可考慮「總會議數 &lt; 5 不列入風險」或單獨標示為「新進觀察」。
3. **會期邊界**：若 admin 可設定會期起迄，則以設定為準；否則以資料庫會議日期自動推算。
4. **快取**：關注名單計算較重，可做短期快取（如 5 分鐘），避免頻繁重算。
