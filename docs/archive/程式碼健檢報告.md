## 二、按鈕同步機制 ✅（已優化）

### 已具備的防護
| 按鈕 | 機制 |
|------|------|
| 簽到提交 | `submitting` 防重複提交、`disabled` |
| 儲存簽到 | `actionLoading[`save-${member.id}`]` |
| 統計載入 | `statsLoading`、`disabled` |
| 抽獎 | `isSpinning`、`disabled` |
| 刪除中獎 | `deletingWinnerId === record.id` |
| 登入 | `loading`、`disabled` |

### 本次新增
- **同步到 Sheets**：加入 `syncToSheetsLoading`，避免連點重複呼叫 API

### 批量操作
- 批量簽到/刪除會先清空 `selectedMembers`（樂觀更新），按鈕會立即隱藏，降低重複觸發風險

## 三、無窮迴圈風險 ✅

### 已檢查的 useEffect

| 位置 | 依賴 | 風險 | 狀態 |
|------|------|------|------|
| checkin 載入+定時刷新 | `[loadData]` | 低 | ✅ 已調整（原含 submitCheckin 等會頻繁變動） |
| attendance 背景刷新 | `[activeTab]` | 無 | ✅ |
| attendance 統計載入 | `[activeTab, statsDateStart, statsDateEnd, loadMemberStats]` | 無 | ✅ loadMemberStats 為 [] |
| attendance 切換日期 | `[selectedDate, meetings]` | 無 | ✅ |
| reports 載入 | `[activeTab, statsDateStart, statsDateEnd, loadMemberStats]` | 無 | ✅ |

### 已修正
- **checkin 頁**：原本 effect 依賴 `[loadData, selectedMember, submitting, submitCheckin]`，每次選會員或提交都會重跑並重建 interval。已拆成兩段 effect，並以 ref 傳遞 keydown handler，避免不必要重跑。

## 四、資料流順暢性 ✅

### 已具備機制
- **單一情境 API**：`/api/attendance/context` 一次取得 members、meetings、checkinsByDate、meetingStats
- **樂觀更新**：批量簽到/刪除、刪除中獎記錄皆先更新 UI 再打 API
- **Ref 避免閉包**：`selectedDateRef`、`checkinsByDateRef` 供背景刷新與日期切換使用
- **快取**：`lib/cache.ts` 搭配 members、meetings、prizes API
- **速率限制**：背景刷新遇 429 時暫停 5 分鐘

### 建議（選做）
- 簽到成功後目前會再打 `/api/checkins` 取得最新資料；若流量偏大，可改為僅做樂觀更新，依定時刷新或下次操作更新
- 抽獎頁 `loadData(false)` 可視需求加上防抖，避免短時間多次觸發
